# ScholarQuant AI: 版本推进与分工手册



**项目愿景**：打造一个不仅能“算账”，还能“预测未来”并“听懂人话”的大学生智能财富伴侣。

------



## 🚀 第一阶段：v0.1 - 核心逻辑 MVP (最小可行性产品)



**目标**：跑通“生活费 + 定投”的数学逻辑，不联网，数据写死，验证现金流模型是否成立。



### 1.1 功能切片 (Feature Slicing)



- **时间轴引擎**：生成从“入学日”到“毕业日”的完整时间序列，精确标记出“学期中”与“寒暑假”。
- **静态记账**：支持输入初始资金（黄金/纳指/现金），并按月扣除生活费。
- **定投逻辑验证**：实现“每交易日卖出 X 元黄金，买入 X 元纳指”的资金流转逻辑。
- **结果输出**：计算毕业那一天的剩余总资产。



### 1.2 技术分层 (Tech Layering)



- **后端 (FastAPI)**：
  - 建立 `SimulationEngine` 类。
  - 实现 `generate_timeline(start, end, holidays)` 函数。
  - 实现纯内存计算，暂不接数据库。
- **前端 (Vue3)**：
  - 使用 `Naive UI` 的 `NDatePicker` 选择入学/毕业时间。
  - 使用简单的 `NStatistic` 展示“毕业剩余资金”。



### 1.3 项目分工 (Division of Labor)



| **角色**     | **任务描述**                                                 |
| ------------ | ------------------------------------------------------------ |
| **后端开发** | 编写 Python 脚本，用 Pandas 生成时间表，实现 `if holiday: spend = 0` 的逻辑。 |
| **前端开发** | 搭建 Vite + Naive UI 框架，画出最基础的表单页面。            |

## 📈 第二阶段：v0.5 - 动态数据与可视化 (The Data Integrator)



**目标**：联网获取真实行情，引入 SQLite 缓存，实现可视化的资产变动曲线。



### 2.1 功能切片



- **数据获取层**：接入 `Akshare` (国内ETF) 或 `yfinance`。获取 518880 (黄金) 和 513100 (纳指) 的历史数据。
- **数据缓存**：将获取的数据存入 SQLite，避免重复请求导致 IP 被封。
- **历史回测**：让用户选择“如果我在 2020 年入学”，系统使用真实历史数据跑一遍定投策略。
- **可视化**：展示资产堆叠图（黄金逐渐减少，纳指逐渐增加的过程）。



### 2.2 技术分层



- **数据层**：设计 `market_data.db` (SQLite)，表结构包含 `date, symbol, close, change_pct`。
- **后端**：增加 `DataFetcher` 服务，使用 `APScheduler` 每天收盘后更新数据。
- **前端**：引入 `ECharts`，绘制动态的时间序列图；使用 `NDataTable` 展示每月的详细收支流水。



### 2.3 项目分工

## 🎲 第三阶段：v1.0 - 蒙特卡洛与量化内核 (The Quant Core)



**目标**：引入概率论，从“回测历史”升级为“预测未来”，回答“我有多少概率会破产”。



### 3.1 功能切片



- **蒙特卡洛模拟**：基于历史波动率和收益率，生成 5000 种可能的未来市场走势。
- **情景分析 (Scenario Analysis)**：
  - **牛市模式**：假设年化收益率 +20%。
  - **熊市模式**：假设发生类似 2000 年或 2008 年的崩盘。
- **生存概率计算**：输出一个百分比，“你在大四毕业前资金链断裂的概率是 12%”。
- **置信区间图**：画出资产未来的“喇叭口”预测图（包含 95% 最好情况和最坏情况的范围）。



### 3.2 技术分层



- **数学层**：使用 `NumPy` 进行向量化计算（极速生成随机数矩阵），避免使用 Python `for` 循环。
- **算法层**：实现几何布朗运动 (GBM) 算法：$dS = \mu S dt + \sigma S dW$。
- **前端**：增加“压力测试”开关，一键切换牛熊市视角。



### 3.3 项目分工



| **角色**       | **任务描述**                                                 |
| -------------- | ------------------------------------------------------------ |
| **量化研究员** | 确定 GBM 模型的参数（漂移率 $\mu$ 和 波动率 $\sigma$），验证模拟的收敛性。 |
| **后端优化**   | 优化 NumPy 计算性能，确保 5000 次模拟在 1 秒内返回结果。     |

## 🤖 第四阶段：v2.0 - AI 赋能与智能决策 (The AI Copilot)



**目标**：引入 LLM，降低使用门槛，提供人性化的“理财顾问”服务。



### 4.1 功能切片



- **自然语言配置**：用户输入“我大一，有20万，想激进点投资”，AI 自动填好所有复杂的参数表单。
- **智能研报生成**：AI 读取蒙特卡洛模拟的 JSON 结果，生成一段文字：“⚠️ 警告：你的策略过于激进，建议预留 3 个月生活费在余额宝中。”
- **交互式问答**：用户可以问“为什么我的黄金变少了？”，AI 解释“因为你开启了定投，资金正逐步转移到纳斯达克。”



### 4.2 技术分层



- **AI 编排层**：引入 `LangChain` 或 `Instructor` (Pydantic for LLM)。
- **API 层**：接入 OpenAI (GPT-4o) 或 DeepSeek-R1 (高性价比数学推理)。
- **通信层**：实现 **SSE (Server-Sent Events)**，让 AI 的回答像打字机一样流式传输到前端，无需等待。
- **前端**：增加悬浮聊天球 (Floating Chat Bubble) 和 Markdown 渲染器。



### 4.3 项目分工



| **角色**      | **任务描述**                                                 |
| ------------- | ------------------------------------------------------------ |
| **AI 工程师** | 设计 Prompt Engineering，确保 LLM 输出稳定的 JSON 格式；调试 SSE 流式接口。 |
| **产品设计**  | 设计 AI 与现有图表的交互逻辑（例如：AI 提到“熊市”时，图表自动切换到熊市视图）。 |
